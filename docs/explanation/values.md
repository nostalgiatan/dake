# 文件、载体与记录

文件不是值。值是读完之后留在变量里的东西。读取从下往上分三层，上一层不能省略下一层。

载体是内存里的第一种形态，只有字节和已经成功解码的字符串。非法 UTF-8 不是字符串，读取失败，也不替换字符。字节和字符串不能相加，也不能用 `str` 或 `num` 互相转换。打印字节会失败，因为打印需要可读文本，而字节的长度和顺序才是它的意义。

编码是载体之间的函数，不是文件类型。`base64.encode` 只接受字节，`base64.decode` 只接受字符串。文本进内存走 `files.read.str`，它在内部做 UTF-8 校验，不暴露成可以省掉的转换。这样「把文件读成文本」和「把字节编成 base64」不会变成同一种隐式步骤。

结构建立在某一种载体上。`layout` 决定怎么切，不决定编码。`whole` 表示整份载体就是一个字段。`lines` 表示文本的第一行和其余行。`split` 用 `sep` 把一段文本切成 `str`、`int`、`float` 或 `bool`。引号是这个切分规则的一部分：分隔符出现在字段里时，字段用双引号包住，这样「个数不符」仍然表示切分失败，而不是表示内容里碰巧有逗号。`width` 不走分隔符。它按每个字段声明的宽度从字节里取一段，因为字节没有可见的分隔符。

整数和小数是两种值。`1` 与 `1` 相加仍是整数，避免计数在运算后变成小数。只要有一侧是小数，结果就是小数。JSON 里的小数因此能进 `float` 字段，而不会在解码时被丢掉。没有结构的 JSON 对象是对象值，键用字段或字符串下标读取。记录仍然记住自己的结构，所以列表字段和嵌套字段要按那个结构来填。

记录记住自己的结构。字段写在 `${...}` 后面，那个点是字段，不是模块路径。`update` 得到一份新记录，因为变量绑定的是值，改一个字段不应改掉仍指着旧记录的其他名字。`files.write` 因此不必再传结构名。`pack` 也是这样：收进包的字节由记录自己的结构编码，清单记下这个结构。`unpack` 读同一目录的清单，按这个结构把文件解码回记录，所以包不是只写一次。

多行文件不由 `files.read` 按行拆开。一行是一条记录，很多行是记录的列表。`files.rows` 就是按这个形状读入：每一行仍先解码成记录，结果是列表。`text.lines` 仍得到字符串列表，需要自己 `text.decode` 时再用它。`each ... in files` 仍只遍历收进包的路径，因为打包收集的是路径，不是文件内容。`list.add` 返回新列表，和 `update` 一样不改原来的值。下标取出一个元素，切片取出半开区间里的一段，二者都得到新的值，不改原来的列表。`stop` 离开的是当前这一层 `each`，列表本身不变。

磁盘按 1 MiB 一块读入。脚本要的是整份字节、整段字符串或一条记录时，这些块仍会收成一个值，因为解码和 `check` 要看完整内容。压缩把块交给 zstd。打进包的副本在加密时按块写出，不再同时留下整段明文和密文；密文是分块帧，旧的整段密文仍能解开。`block` 布局是例外：每个字段单独一块，读完一块就放进记录，再读下一块，所以峰值是已经解码的字段加上当前这一块，而不是整份文件再加记录。`files.field` 连记录也不组装，一块处理完就丢掉。清单上的共享密钥签名盖的是包名、版本、依赖和各文件的 blake3，不是再存一份文件。公钥签名盖的是清单原文。核对时先验这份签名，再按 1 MiB 一块重算清单里的 blake3，不把整个文件收进内存。换掉文件而留下旧清单也会失败。私钥留在签名的机器上。记录里最终仍有全部字段，除非走 `files.field`。

脚本、清单、密钥和证书都是短文本，映射到地址空间省不下可观的页。映射只是让缺页把同一份内容再装进页缓存，解码时仍要复制出来。目录监视期间文件还可能被截短，映射上的访问会变成信号，而按块读入只是一次失败的读取。因此这里不把文件映射进地址空间。

`sys.host`、`sys.cpu`、`sys.mem`、`sys.disk` 和 `sys.disks` 读的是这次运行所在的机器，不是文件。它们返回的对象没有结构，因为宿主没有一份可以写进包里的记录定义。占用、剩余空间和主机名每次运行都会变，所以不能当成包的内容，也不会进清单。

列表、字节、记录的字段和对象在复制时只增加引用计数。要改其中一项时，才取出一份自己的副本。临时名字仍然只放在槽里。这样 `await` 合并结果、`get` 读变量，不会把整份记录再抄一遍。
