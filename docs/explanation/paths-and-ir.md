# 路径与中间表示

dake 的脚本表面只有一种块：冒号加缩进。关键字全是小写。这样词法不必同时认识 `set` 和 `IF`，块的结束也不必靠「下一个是不是某个关键字」。

可调用的东西必须有路径。`::` 表示模块，`.` 表示模块里的行为。点后面已经处在名字的位置，所以 `set` 这样的关键字在这里只是字段或行为名，不会再开始一条语句。`use` 把另一个文件登记到别名上。两个文件都可以定义 `clean`，因为降级之后的名字是文件路径加上行为名，而不是源码里的短名。没有定义处的单词不能出现在管道里，否则管道无法指向一段真实的规则。管道和行为一样可以带参数：调用时把值放进这些名字，步骤里的 `${名字}` 读到的就是这次调用的值。

文件路径在编译和执行时走同一套检查：去掉开头重复的 `./`，拒绝空路径、空字节、出现 `..` 的路径，以及单独的 `.` 段。运行时还会顺着符号链接走。链接目标必须是相对路径，并且同样通过这套检查，所以不能借链接跳到绝对路径或父目录。`use`、输出目录、`dir` 和运行时的读写都经过它。行为体在载入执行器时包进共享指针，之后调用只增加引用计数，不再复制整段指令。列表、字节、记录字段和对象也是如此。临时名字以 `#` 开头，写入时只进槽，不再为上下文复制一份。

执行器不解释源码。`dake check` 和 `dake run` 都经过同一条编译：语法树、解析 `use`、中间表示。中间表示里的调用已经是解析过的路径，所以同一次编译里每条路径只查找一次。`await` 在这一层检查写入的名字是否相交；相交就停止编译，不相交才并行，并把各自写入的变量合并回去。并行发生在阻塞线程上，因为文件和网络调用会占住线程。每个分支看到的是进入 `await` 时的结构、网络目标和加密状态，也能调用同一份行为。分支里新设的网络目标不会写回外面。

内置能力走同一条调用，例如 `files`、`data.comp`、`log.info`。它们不是另一套语句。结果进入 `set` 的名字，或行为里的 `result`，这样下一步读到的是变量，而不是执行器私自造出的键。
