## Learned User Preferences

- Discuss language design in Chinese and review whether the grammar is correct and complete before large syntax changes.
- Import other script files with `use`, not `import`. Paths use `::` for modules and `.` for behaviors.
- Scripts should be compiled to an intermediate representation before execution, and defined behaviors must be named so pipelines can call them.
- After language changes, add language tests and run `cargo test --bin dake` with one filter before treating the work as done.
- Keep project docs in the Diátaxis layout under `docs/` (tutorials, how-to, reference, explanation), and update them when the language changes. Do not leave scratch reports in the repo root.
- When implementing a written plan, do not edit the plan file.

## Learned Workspace Facts

- `dake` is a Rust DSL packaging tool: scripts describe data packages, then the CLI (`check`, `ast`, `run`) validates, compresses, and encrypts them. Scripts also read and write structured file contents as bytes, text, lists, and records.
- The main program is split into `dsl` (lexer, parser, AST), `executor`, `data`, and `cli`. The `error` crate is what `dake` actually depends on. `rstream`, `sys`, and `transaction` stay side libraries and are not used by the executor. `sys.host`, `sys.cpu`, `sys.mem`, `sys.disk`, and `sys.disks` are one-shot host snapshots via sysinfo. Host facts must not be written into the package manifest.
- Current syntax is one lowercase-keyword language: blocks end by indentation after a colon, variables are read only as `${name}`, and behaviors are `action name(params):`. Values include integers, decimals, strings, bytes, lists, records, and objects that have no struct. List, Bytes, Record fields, and Object clone by Arc reference count.
- `dake run` parses, resolves `use "file" as alias` at compile time, lowers to IR, then executes. Missing or duplicate imports are compile errors. `await` runs on blocking threads when the names written do not overlap; branches share structs, actions, net targets, and crypto as a snapshot.
- `files.rows` and `files.write.rows` read and write one `split` or `json` record per line and hold the whole list. Large line files use `files.each` (one row to an action, no list) and `files.write.row` (append one line). `append: true` on `files.write.rows` only checks the last byte. `list.map` and `list.keep` call a one-parameter action that must `set(result, ...)`.
- `pack(name, records)` encodes rows of one struct into the package and stores that struct id on the manifest item. Copies taken by `files` leave `struct` empty. `pack` requires `lib`. `unpack(path)` reads those rows back from the in-memory pack or from `manifest.json` beside the file. Manifest `depends` and `replaces` are `"name version"` strings. `sign` is a shared-key MAC and is not copied into the package. `files.seal` / `files.unseal` use Ed25519; the private key stays out, and `files.unseal` also rehashes each file. `files.verify` opens the dependency and replacement directories and checks name, version, hash, and signature.
- `files.decry(key_path, ciphertext_bytes)` decrypts package bytes with the hex key in `dake.key`. The result is bytes. New ciphertext is chunked and starts with `DAKE` and version byte `2`; ciphertext without that frame is still decrypted as one block.
- `net.url` sets the current `http` or `https` target; `cert` and `key` together select TLS. `net.get` and `net.post` use it and return bytes or one decoded record. `net.accept` handles one request and returns the action `result`; omit `cert`/`key` for plaintext. A two-parameter action receives the header object. `url`, `dir`, `serve`, and `route` are the continuous-run system. `serve` handles one event at a time unless `workers` is set (1–64), which also parallelizes directory files; extra connections queue up to 32. Cross-connection state is only names declared with `share`. SIGINT or SIGTERM ends `serve` after the current event and still writes the package. Network failures use the same error format.
- Preflight code 4037 checks straight-line literal paths before execute. Path check is shared (`pathcheck::tighten`): strip a leading `./`, and reject empty, NUL, `..`, and `.` segments. Runtime follows a symlink only when the target is relative and passes the same check. Absolute symlink targets are rejected.
- Parse, compile, and run failures use one format: the existing explanation, `位置: file:line:column`, and a `建议:` repair hint.
